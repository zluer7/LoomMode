# LoomMode 2.0.0 — release candidate for Owner acceptance

LoomMode organizes a sequential AI development team. The Owner defines goals,
important authorization and final acceptance. Decision leads professional
judgments within that authorization and is the sole Owner-facing workflow
interface. Promoter autonomously organizes Tasks; Constraint produces bounded
execution inputs; Discussant independently challenges proposals; Executor
implements, tests and reports. Engine/Host preserves actual permissions,
Writer, evidence, resource limits and Gates. Ordinary Tasks have no extra
Decision sign-off. Final text does not create permission.

**Status: OWNER_ACCEPTANCE_PENDING / PUBLICATION_NOT_AUTHORIZED.** Version
2.0.0 is a newly built candidate, not a renamed rc.3 archive or an announcement
of publication. Start with [START_HERE.md](START_HERE.md), then the complete
[installation guide](AGENT_INSTALL.md). Use the full archive; the wheel alone
does not contain the first-use tools, roles or config.

| --- | --- |
| Platform | Windows, Python >=3.11, ordinary local user environment |
| Models | Codex-only through the user's legitimate compatible installation |
| Workflow | Bounded managed single Task; manual progression, no automatic Git commit |
| Input | Explicit Owner authority, fresh isolated workspace and fixed tests |
| Safety | Actual Host checks, Writer, bounded usage, faithful failure/UNKNOWN records |
| Roles | Current fixed responsibilities, public Part I projections, empty source-project experience |
| Distribution | Standard-library runtime, offline wheel, complete first-use package and checksums |

Prior bounded live evidence supports TASK_ACCEPTED and normal manual Host close.
Another physical-device identity was not independently certified. This build
adds the current role/Prompt definitions and packaging corrections; it does not
repeat that live run. See [release notes](RELEASE_NOTES.md) and
[known limits](KNOWN_ISSUES.md). Existing project's State/Binding/Grant/Records
must not be overwritten. There is no automatic project migration or recovery.

## Roadmap and experimental areas

Multi-AI interfaces, broader delegated workflows and accepted-release Binding
exist in development under separate prerequisites. They are outside this first
public support promise. General recovery, unattended multi-Task engineering,
arbitrary Codex versions and cross-platform support require further dedicated
validation; no schedule or guarantee is implied.
