# 项目概览

LoomMode 面向需要持续协调、验证和交接软件开发工作的个人与小团队。它把任务组织、范围制定、审阅、实现和验收接入同一个本地流程。Owner 提供开发目标、现有技术依据、可改范围与完成标准，并保留重要方向和权限决定。

| 角色 | 责任 |
| --- | --- |
| Decision | 统筹授权内的重要取舍与异常，向 Owner 解释需要决定的问题。 |
| Promoter | 组织任务，依据约束、报告和验证结果判断任务是否接受。 |
| Constraint | 把任务意图变为可执行、可检查的边界，处理讨论意见并定稿。 |
| Discussant | 独立检查方案、约束和目标之间的偏差，提出有依据的意见。 |
| Executor | 核对现场，在授权范围内实现、验证、修复并报告。 |

在一个导出功能任务中，Owner 可以要求使用已有记录生成 CSV 并保护现有保存行为。角色据此明确改动范围和固定测试，Executor 交付实际改动及验证结果，Promoter 据此判断任务是否接受。这样，后续工作可以回看目标、改动、测试结果和待处理问题。

阅读 [正式项目说明书（PDF）](LoomMode_2.0_说明书.pdf) 可了解设计理念、实践案例与后续方向。从 [快速开始](QUICK_START.md) 了解当前操作方式，或查看 [技术架构](ARCHITECTURE.md) 和 [支持说明](SUPPORT.md)。
